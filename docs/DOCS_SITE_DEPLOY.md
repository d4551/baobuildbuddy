# Docs Site Deployment

How the public download site (`docs/`, served at <https://baobuildbuddy.com>) gets published
to the FTP-backed static host.

## What ships

`docs/index.html` is only half the site. The page links to files that live in the canonical
desktop release tree, so publishing `docs/` alone yields a download page whose every download
returns 404. The full bundle is:

| Path in the bundle                | Source                                             |
| --------------------------------- | -------------------------------------------------- |
| `index.html`, `favicon.svg`       | `docs/`                                             |
| `assets/docs.generated.css`       | generated by `build:docs-site` (Tailwind + daisyUI)  |
| `assets/tux.svg`                  | `docs/assets/`                                      |
| `releases/manifest.json`          | generated by `build:docs-site` from `provenance.json` |
| `releases/sha256.txt`             | `packages/desktop/releases/`                        |
| `releases/provenance.json`        | `packages/desktop/releases/`                        |
| `releases/<platform>/<artifact>`  | `packages/desktop/releases/<platform>/`             |

The bundler takes the published layout from `releases/manifest.json` rather than re-deriving
it, so the page, the manifest the page fetches, and the files on disk cannot drift apart.

## Publishing

```bash
bun run docs-site:bundle       # build:docs-site + stage into dist/docs-site
bun run docs-site:deploy       # upload dist/docs-site over FTPS
```

`docs-site:deploy --dry-run` prints the upload plan and connects to nothing — use it to check
the file list and the resolved host before publishing.

### Release binaries are Git LFS objects

`packages/desktop/releases/*` are tracked with Git LFS. In a checkout without `git lfs pull`
they are ~133-byte pointer files, and the bundler **fails closed** rather than publishing them
as if they were installers. Either run `git lfs pull` first, or pass `--skip-artifacts` to
publish a page-only update (the existing binaries on the host are left untouched, but any
newly-listed file will 404 until a full bundle is published).

## Credentials

Credentials are read from the environment and are never stored in the repo. The deploy refuses
to run unless all three are set:

| Variable                   | Required | Default | Notes                                            |
| -------------------------- | -------- | ------- | ------------------------------------------------ |
| `BAO_DOCS_FTP_HOST`        | yes      | —       | FTP hostname of the static host                  |
| `BAO_DOCS_FTP_USER`        | yes      | —       | FTP username                                     |
| `BAO_DOCS_FTP_PASSWORD`    | yes      | —       | FTP password                                     |
| `BAO_DOCS_FTP_PORT`        | no       | `21`    |                                                  |
| `BAO_DOCS_FTP_REMOTE_ROOT` | no       | `/`     | Remote directory the site is served from         |
| `BAO_DOCS_FTP_SECURE`      | no       | `true`  | Explicit FTPS (`AUTH TLS`); `false` sends the password in clear text |
| `BAO_DOCS_FTP_TIMEOUT_MS`  | no       | `30000` |                                                  |

## CI

`.github/workflows/deploy-docs-site.yml` publishes on three triggers:

| Trigger | Binaries come from | Use |
| ------- | ------------------ | --- |
| `workflow_run` after a successful `desktop-release` on `main` | the `desktop-releases` artifact that job assembled | a fresh all-OS build reaches the site without committing binaries |
| `push` to `main` touching the site, release tree, or deploy scripts | the committed release tree (checkout with `lfs: true`) | page and copy changes |
| `workflow_dispatch` | committed release tree; `skip_artifacts` input for page-only hotfixes | manual re-publish |

Every run verifies the release set (`verify:desktop-releases`) before staging, so a broken or
incomplete artifact set fails the deploy instead of shipping.

The all-OS build itself lives in `.github/workflows/desktop-release.yml`, which builds on
`macos-14`, `windows-latest`, `ubuntu-24.04` and `ubuntu-24.04-arm`, then assembles and verifies
the canonical release tree.

Set the three required values as repository **secrets** (`BAO_DOCS_FTP_HOST`,
`BAO_DOCS_FTP_USER`, `BAO_DOCS_FTP_PASSWORD`); the optional ones can be repository
**variables**. Anyone who has handled the password in plain text — a chat message, a ticket,
a shell history entry — should rotate it at the host before it is stored as a secret.
